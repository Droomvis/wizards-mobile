2. BESLISSINGEN DIE BLIJVEN GELDEN
============================================================
Algemeen:
 (1) Effecten op de eigen kant: DIRECT. Alleen effecten met een slachtoffer (Damage/Inflict) via stack-entry.
 (2) OnEnterPlay/OnLeavePlay alleen via AUTOMATISCHE bronnen. Handmatig slepen, zoom-knoppen
     (Terug naar hand/Discard/Banish), handmatige tellerknoppen en pre-game Destiny-plaatsing vuren niets.
 (3) StartOfTurn na het trekken van 5; EndOfTurn en directe rest-effecten na hand-limit-discard.
 (4) Actiekosten tellen als bestede actie (Slumber tikt).
 (5) Heal valt buiten scope.
 END TURN-volgorde: Rest -> rest-Inflict (stack) -> hand-limit/Burdens -> OnDiscard -> directe
 rest-effecten -> EndOfTurn -> beurtwissel -> trek 5 -> StartOfTurn.
 Dispatch-volgorde per trigger-moment: directe acties (Draw/GainAction/GainSpite) -> kaart-effecten
 (Exhaust/Ready/AddCounter/RemoveCounter, straks ReturnToHand/Banish) -> Damage -> Inflict.
 fireDirectTriggerEffects = fireDirectActionEffects + fireCardTriggerEffects.

Fase C (C1-C9):
 C1 ModifyShield: waarde mag negatief, shield >= 0; wordt als LAATSTE gebouwd, wacht op het
    damage/shield-model (takeStackDamage trekt nu geen shield af).
 C2 Ontbrekend/niet-in-play doelwit: log "niet toegepast" (type card-skip), geen crash, geen fallback.
 C3 Exhaust op exhausted / Ready op ready: geen wijziging + log (tap-skip).
 C4 Exhaust via effect zet Slumber-teller zoals de knop (setTapped).
 C5 Banish/ReturnToHand "chosen": op eigen EN vijandelijke kaarten, via targetRef, alleen bij OnResolve.
 C6 Banish alleen op Manifestation/Hex/andere permanents; Destiny overslaan met log tot er een
    Destiny-banish-regel bestaat.
 C7 ReturnToHand/Banish DIRECT (geen stack-entry; OnResolve impliceert al een reactievenster;
    kan later stack-entry worden).
 C8 Een enkele checkbox `cardEffects`.
 C9 De handelende client past toe + saveArena synchroniseert (auteur denkt mogelijk aan een
    hosting-browser-architectuur voor de tegenspeler).
Summoning sickness: kaart met Slumber>0 komt exhausted in spel met witte teller = Slumber, enkel in
 resolveStackTop (handmatig slepen/pre-game Destiny niet). Slumber 0 = ready. Exhausted kaart kan
 ExhaustSelf niet betalen (canPayCosts).
9b-2: AddCounter zwart = schade via addCounterToInstance(auto:true) incl. Vulnerable/dood + OnLeavePlay
 eenmalig, geen zone/damageType-check; RemoveCounter zwart = heal; per-teller-lus stopt als kaart sterft;
 counterColor verplicht (ontbreekt -> skip-log + waarschuwing); wit op ready kaart doet niets;
 RemoveCounter wit tot 0 maakt niet vanzelf ready; nooit onder 0 (log "niets te verwijderen");
 AddCounter zwart moet zich in Fase D voor OnDamaged gedragen als Damage.
Mobiele editor (Wizards_Mobile.html, sw-mobile.js): NIET nodig; Android dient alleen om kaarten te raadplegen.

    Andere types (Wizard, Burden): voorstel — Wizard overslaan met log; Burden toegestaan voor
    ReturnToHand? Laat de auteur kiezen.
 Q6 OnBanish blijft ONGEVUURD tot Fase D (ook bij Banish via effect).
 Q7 Gebruik van `value`: niet van toepassing; effectIssues geeft geen waarschuwing voor value 0.
 Q8 Volgorde in dispatch: na Exhaust/Ready/AddCounter/RemoveCounter, voor Damage/Inflict.
 Q9 Checkbox: blijft `cardEffects`; label bijwerken.
